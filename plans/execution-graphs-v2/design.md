## Root scheduling contract

`RootExecutionLimits` has optional `maxConcurrentWork` (positive safe integer), `maxExpandedNodes`, `maxWorkAttempts`, `maxPlanRevisions` (nonnegative safe integers). Omission preserves previous unlimited aggregate behavior. One slot means one leaf provider request/stream or actual controlled tool/function invocation. Graphs, repeats, Agents, planner orchestration and preparation/transformation hold no slot. Local caps can narrow this ceiling. Leaf callbacks may not initiate nested controlled work: detect and reject it, rather than waiting while holding a parent permit or allowing hidden reentrant oversubscription.

`RootExecutionController` supplies `expand(ids)`, `revision(id)`, `run(kind,id,execute,signal?)`, stream-lifetime acquisition, snapshots and events. Unique logical node incarnations are lifetime expansions; every actual leaf dispatch is a work attempt; every committed materialized revision is a plan revision. Removed nodes do not refund counters. Recovered completed work, materializations and recorded responses are reused without new dispatch attempts. Queue cancellation removes waiters; started work releases on settlement, including throws. Tools release before model-output transformation; models acquire after preparation.

The same controller flows through RunOpts, RunContext and ExecutionServices to ToolExecutor and provider boundaries, including Agent-local tools. A persistence port atomically records admission/counters before effects and restores monotonic totals under the task fence. The concurrency claim covers controlled SDK dispatch ownership; lease fencing cannot stop an already sent remote request. Unknown remote effects remain unresolved until destination reconciliation, rather than being treated as stopped because a lease expired.

An owned permit exposes `cleanup(execute)` for stream iterator finalization after cancellation. It preserves ownership, concurrent-callback and nested-dispatch checks, grants no new attempt, and releases only after closure settles. Effect dispatch reserves its permit while the action is still prepared and keeps it through receipt resolution and durable settlement. Local admission failures therefore cannot be confused with uncertain remote acceptance.

## Durable graph journal

Use a runtime-validated `agentium.graph.v1` extension in the existing bounded task aggregate. Bind definition ID/version/catalog descriptors, original JSON input, root limits, absolute deadline and executable versions to the task's immutable manifest/policy/grants identity. Persist materialized plans/revisions, raw proposals and causal observations, node input digests and lifecycle, attempt/fence ownership, completed outputs, repeat decisions, recorded model decisions, budget state, admission audit, cancellation and superseded evidence. Reject incompatible/corrupt records and changed bindings/inputs before resumed effects.

`DurableGraphJournal` is constructed with the store, task key, active fence and admitted definition. It initializes/validates records; exposes fenced `mutate` and validated read-only `snapshot`; owns `node(id,binding,input,execute)`, `model(id,request,execute)`, `decision(id,compute)`, and action-ledger-backed `effect(input,connector,resolveResult)`. All persisted values are finite JSON. Node completion is saved before successors can run. Completed nodes return recorded outputs. Running nodes restart under a new fenced attempt; failed/cancelled nodes remain terminal; uncertain outcomes require reconciliation before a new fenced attempt. Structural decisions are reused after recovery. Terminal task state is not silently reset.

Supported durable bindings: host-declared pure JSON tools/functions; controlled effects with a versioned DurableActionConnector and immutable receipt resolver; Agents restricted to approved tools plus recorded complete model responses; static graph/repeat orchestration using supported catalog children. Unsafe arbitrary tools, dynamic resolvers/handoffs, non-JSON results and effects without a declared safe recovery policy are rejected before node admission. Function/Agent implementation versions and argument/output schemas are host-owned, never executable code from a proposal.

Construction snapshots all plain program/catalog policy data, including nested argument templates, limits, grants and budgets. Opaque schema/provider/Agent/callback implementations remain host-attested bindings. Catalog and manifest descriptor checks precede episode and tool admission. Sandbox environment values contribute only hashes to the descriptor; the SDK does not expose their values to the planner.

Before ledger intent, append-only `effect.origin` evidence records the originating binding ID/version, logical node/tool call, arguments and catalog/definition/manifest identity. Recovery verifies its prepared hash/idempotency key and resolves that exact operation. Connector version plus destination alone is ambiguous and must never select a reconciler.

An interrupted Agent restarts from node entry with the same recorded model responses at the same operation positions. Each cached response is request-digest checked and persisted before its tools become eligible. Logical effects use node incarnation + recorded call ID/position, bound to operation/version/input; attempts/fences are separate identities. Confirmed receipts are reused; unknown/executing actions reconcile first or return explicit recovery required. Interrupted model calls retain conservative charges; a new request consumes remaining budget. This is recovery with recorded decisions, not exact playback of arbitrary host behavior.

The adapter retains full harness budget state before actual dispatch and after settlement. Hydration includes used/reserved calls/tokens, tool admission identities, protected finishing capacity and unknown usage. Crashed reservations become conservative charged unknown usage; allowances/deadlines never reset. Replayed tools still undergo authorization, while stable admission identities prevent duplicate budget charge. Root cancellation is persisted and polled with lease renewal. The supervisor needs an explicit reconciliation hook before its unknown-action guard; reconciliation cannot be hidden in an unreachable normal handler.

Durability is advertised only by the graph recovery adapter after requiring durable atomic CAS/fence storage, admitted catalog/definition validation and the journaled execution ports. Existing workflowDriver stays non-durable and old checkpoint formats remain unchanged. Hosts own backend lifecycle, credentials, schema/implementation versioning, receipt retention, destination idempotency and reconciliation. No exactly-once external-execution claim.

## Proposal, planner and streaming

A strict JSON proposal contains a schema version, revision and nodes with unique ID, binding ID/version, argument template, control dependencies and data references; optional local concurrency/merge fields are bounded by host limits. No code or grant claims. A host-approved catalog validates supported operations, literal arguments, declared input/output reference paths, pure/effect recovery compatibility and nested binding depth. Resolve and validate concrete arguments again before effect intent; future data cannot be proven by arbitrary Zod refinements at proposal time. Use null-prototype/validated keys and reject unsafe paths.

The optional planner makes tool-free authorized `ExecutionServices.model` or `streamModel` calls with host instructions and proposals/observations in data messages. Invalid proposals have bounded correction ownership and consume ordinary call/token/work budgets. Persist proposed and accepted plans and causal observations. Existing Agent loop remains available.

Streaming uses bounded NDJSON commit frames, each carrying exact `baseRevision` and a complete self-contained candidate DAG. Only complete validated frames can commit. Pending/unprepared nodes may be added, removed or replaced; changed nodes receive new incarnation and expansion charge. Running, prepared, completed, failed or uncertain nodes and their relevant dependency/input bindings cannot change. Commit and node claim serialize under the same journal CAS. Completed effects and superseded pending definitions remain evidence; edits imply no rollback. Late stale commits/settlements fail the fence/generation check.

A producer continues consuming the stream independently of the scheduler. The stream may occupy a model slot, so the parser never awaits effects needing that slot. At capacity one effects wait for stream closure, without deadlock. Malformed/truncated frames, interrupted streams, exhaustion and cancellation retain committed revisions and explicit partial planning evidence. Recovery executes persisted commits rather than resampling historical plans. Byte, frame, depth, node, correction and revision limits bound planning and expansion.

Depth includes the inherited episode depth plus the dependency path level. A child episode starts one level below its owning node; repeat iterations keep that child nesting level. The journal retains episode depth and rejects mismatch on recovery. Static, model-generated and recovered proposals all receive the inherited depth, so dynamic planners cannot reset the bound.
