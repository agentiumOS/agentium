# resource-budget

Extend HarnessBudgets with `finishingTokens`/`finishingModelCalls` (default 0, within finite max limits). Expose immutable snapshots on RunHandle, execution services and final result: tokens/modelCalls/toolCalls each has limit, used, reserved, remaining and protected finishing capacity; null means unlimited. Denied admission does not spend calls. Call slots reserve synchronously before controllers/projection so nested policy calls cannot steal the pending task slot; unused slots release without spending. Token reservations acquire synchronously after projection and capability checks, before provider submission, so concurrent admissions cannot oversubscribe projected capacity. Include projected input (messages, tool definitions, opaque continuation) and bounded output. Host may supply an input token estimator; built-in estimator is advisory, and actual provider usage is authoritative. Hard token guarantees require a conservative host estimate; actual overage is recorded and prevents further ordinary admission.

Settlement is idempotent. Known terminal usage replaces projected tokens; release unused capacity. Failed/cancelled/truncated requests without complete usage consume the projected amount conservatively and increment unknownUsageCalls (not a fictitious zero); reservation itself is always released. Pre-submission failures release without charging. Logical calls count once when submitted, independent of adapter retries. Monetary/physical-attempt accounting remains separate.

`finishModel(role, messages, options)` is a tool-free independent operation like controlModel. It may use protected finishing capacity plus ordinary remainder. It requires an explicit host model binding and role grant, the same options allowlist and complete tool-free result validation. It never marks a run complete: driver output still passes completionPolicy. Ordinary calls cannot consume the reserve, and repeated denials cannot erode it. Tool execution stays under existing grants/policy with no finishing exemption.
