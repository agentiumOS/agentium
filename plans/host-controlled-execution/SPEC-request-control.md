# request-control

Expose shared `ProviderRequestControls` on exported OpenAIConfig/AnthropicConfig and factories: `maxRetries` (Agentium; default 2), `sdkMaxRetries` (default SDK behavior), `timeoutMs` (SDK per-request timeout), `callTimeoutMs` (whole generate/stream lifetime). ModelConfig also accepts per-call `deadline` (absolute epoch milliseconds) and `callTimeoutMs`; earliest deadline wins against constructor call timeout and caller abort. Validate numeric settings. SDK timeouts can be retried; logical deadline/caller cancellation cannot. Backoff is abortable, preserving the caller reason and disposing listeners/timers. Never retry stream iteration, including metadata before the first outward chunk. Close stream transport on cancellation/early return.

`attemptVisibility` is physical only with sdkMaxRetries=0. Existing accounting operation IDs describe logical calls; captureRetryFailure closes one visible SDK invocation and opens the next. Report endpoint fallback through that same boundary. SDK-owned retries remain opaque and exact total physical attempts are not promised. Existing logical model telemetry remains one start/result per invocation. Further tracing confirmed a third generic LLMLoop retry layer (three retries by default). Controlled execution now defaults this layer to zero; an explicit Agent retry config can opt in. Standalone Agent defaults remain compatible. Both generic and adapter retry waits must honor cancellation. A host using a standalone Agent must also set Agent.retry.maxRetries=0 when owning retries.
