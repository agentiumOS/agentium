# resident-history

Canonical records are immutable messages held either resident or in a host archive. Resident messages are the locally retained replay window; request context is a separately validated projection. Introduce a host archive interface (write/read) and references with identity, conversation ID, count and content digest; no bundled backend. Persist references in session snapshots. Acknowledged archival precedes eviction; failed archive or incompatible replay leaves resident data unchanged. Retrieval verifies digest and returns records for host use, not automatic insertion as trusted instructions.

Opt-in runtime history policy limits resident message count at safe model and session boundaries, retaining the latest whole user turn, all tool calls/results and opaque continuation byte-for-byte. An indivisible live turn or host instructions exceeding the configured bound fails explicitly. Providers declare closed-turn eviction support; unknown providers with opaque data must reject unless the host explicitly supplies support. Existing stateless OpenAI Responses full-item replay and Anthropic signed-block replay can evict closed old turns; foreign/unknown opaque envelopes cannot be assumed safe. Core controlled loops receive an optional residency hook so retained loop copies match the supported runtime window. Arbitrary custom-driver/application copies remain host-owned. Completed child transcripts archive in full at successful commit instead of accumulating resident copies across runs. Archive reference metadata is not a bounded payload cache and the host owns its storage lifecycle. Limits apply per active conversation; failure snapshots preserve oversized evidence for inspection.

Session storage is still conversation persistence, not live-run recovery. Future recovery needs versioned execution checkpoints, pending-input claims and safe side-effect continuation; defer it.
